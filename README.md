# 数字当てカード（実物カードのスマホ代替）

1〜60 の数字当てカード6枚を、そのままスマホで見せるためのアプリ。
**手品の本番では、アプリは数字を当てない。** YES / NO の入力も、記録も、結果表示も一切ない。
当てるのはあなた。アプリはカードを見せるだけ。

初回起動のイントロと種明かし、演者用の練習モードは別扱い（後述）。
表示は端末の言語に合わせて日本語 / 英語が切り替わる。

## 遊び方

1. 相手にスマホを渡す
2. 「1〜60 の中から好きな数字をひとつ決めて」
3. START → カードを1枚ずつ見せる（**横に払ってめくる**）
4. 「ある」と言われたカードの**左上の数字**を頭の中で足す
5. 6枚目の次に「あなたの思い浮かべた数字は…」が出る。
   スマホを返してもらって、あなたが数字を言う

左上の数字がそのカードの重み（1 / 2 / 4 / 8 / 16 / 32）なので、
カードの見た目だけで何を足せばいいか分かる。覚える必要はない。

例：「ある / ない / ある / ない / ない / ある」→ 1 + 4 + 32 = **37**

## 操作

| 操作 | 動き |
| --- | --- |
| 左へ払う | 次のカードへ |
| 右へ払う | 前のカードへ戻る |
| 最後の画面の「もう一度」 | 最初から |

カードは指の動きにそのまま追従し、画面幅の 20% まで動かすと抜ける。
足りなければ元の位置に戻る。速く払った場合は距離が足りなくても抜ける。
最初と最後では引っぱっても付いてこないので、行き止まりが指で分かる。

**タップではめくれない。** 手に持ったまま、相手に見せるとき、渡すときに
画面へ触れてしまっても進まないようにするため。
最後の「あなたの思い浮かべた数字は…」の画面も、「もう一度」を押したときだけ戻る。

## 色のギミック（ミスディレクション）

奇数枚目のカード（1 / 4 / 16）は一部の数字が**赤**、
偶数枚目のカード（2 / 8 / 32）は一部の数字が**緑**になっている。

**この色に意味はない。** 相手に「色が手がかりなんじゃないか」と考えさせるためだけの飾り。

その代わり、飾りとして破綻しないよう次を守っている（`verify.mjs` で検証済み）。

- 色は固定ハッシュで決まるので、**何度見せても同じ配色**。実物のカードと同じように矛盾しない
- 各カードちょうど7個。数を数えても法則が見えない
- **左上の数字（＝あなたが読む重み）には絶対に色をつけない**。色と答えが結びつく余地をなくすため
- どの数字も「色がついていないカード」を最低1枚は持つ。
  「この数字はいつも赤」のような単純な法則に見えないようにしている

## 動かし方

Node.js が入っている前提。

```bash
cd number-cards
npm install
npx expo start
```

表示された QR コードをスマホの **Expo Go** アプリ（App Store / Google Play で無料）で読むと、そのまま実機で動く。

ホーム画面に置けるアプリとして書き出したい場合：

```bash
npx expo run:ios      # macOS + Xcode が必要
npx expo run:android  # Android Studio が必要
```

### Web

```bash
npm run web          # 開発サーバー
npm run build:web    # dist/ に静的書き出し（Vercel 用の後処理込み）
```

### TestFlight に上げる

`eas.json` の `production` プロファイルを使う。ビルド番号は `autoIncrement` で自動。
提出先のアプリは bundle identifier から EAS が照会するので、対話に答えるだけでよい。

```bash
eas build --platform ios --profile production
eas submit --platform ios --latest
```

`build` はクラウドで走るので完了まで待つ（`eas build:list` で状況が見える）。
`submit --latest` は直前に成功したビルドを送るので、`build` が終わってから実行する。
バージョン表記（`1.0.0` など）を上げたいときは `app.json` の `expo.version` を変える。

## 中身

| ファイル | 役割 |
| --- | --- |
| `cards.js` | 6枚のカードの中身を**ビット演算で自動生成**（数字のハードコードなし）＋ 色のギミック |
| `ui.js` | カードの見た目。本番・練習の両方で使う |
| `theme.js` | 配色（3種）とフォント（3種）の定義。プラットフォーム別のフォント名もここ |
| `ThemeContext.js` | 選んだ配色・フォントをアプリ全体に配る |
| `i18n.js` | 日本語 / 英語の文言と、端末の言語判定 |
| `App.js` | イントロ判定とモード選択（はじめる / 練習 / 設定） |
| `IntroScreen.js` | 初回起動のイントロ。アプリのほうが手品をする |
| `ExplainScreen.js` | 種明かし。ロゴをタップすると開く |
| `SettingsScreen.js` | 配色とフォントの切り替え |
| `solve.js` | 「ある」と答えたカードから数字を出す。**イントロと種明かしだけが使う** |
| `prefs.js` | イントロを見たか・種明かしを見つけたか・当てた数字・配色とフォントの保存 |
| `PerformanceScreen.js` | 通常モードの画面。**答えを計算する処理は一切ない** |
| `PracticeScreen.js` | 練習モードの画面 |
| `practice.js` | 練習モードの出題と採点。**答えを計算するのはここだけ** |
| `scores.js` | 練習の記録（連続全問正解・ベストタイム・履歴）の保存と集計 |
| `verify.mjs` | 6枚で 1〜60 が一意に表現できるかの検証 |
| `verify-practice.mjs` | 練習モードの出題が本番と同じ理屈かの検証 |
| `verify-intro.mjs` | イントロが 1〜60 を正しく言い当てるかの検証 |

検証は `node verify.mjs` / `node verify-practice.mjs` / `node verify-intro.mjs` で実行できる。

- 全 2^6 通りの YES/NO パターンから復元した数字が 1〜60 を過不足なく覆い、重複しないこと
- 各数字について「その数字が載っているカードの重みの合計＝その数字」であること
- 色のギミックが答えと無相関で、単純な法則には見えないこと

を機械的に確かめている。

## イントロ（初回起動）

インストールして最初に開いたとき、**アプリのほうが手品をする**。

1. 「1〜60 の中から好きな数字をひとつ思い浮かべてください」
2. カードが1枚ずつ出るので、使う人自身が「ある / ない」を押す
   （2つのボタンは**完全に同じ体裁**。片方を目立たせると答えを誘導しているように見えるため）
3. 「あなたが思い浮かべたのは」→ 間 →**37**→「ですね？」
4. 「どうして分かったと思いますか？ その理由は、このアプリのどこかに隠してあります」

**仕組みを知っている人は最初の画面からスキップできる。**
スキップした人には種明かしを探させる意味がないので、「発見済み」の扱いにしている。

全部「ない」と答えられた場合（＝ 0）は言い当てられないので、聞き直す。

### 種明かし

**ロゴ（金の菱形）をタップすると開く。**

まだ見つけていない間だけ、ロゴがゆっくり明滅する。
「どこかに隠してある」と言われて途方に暮れないための、控えめな道しるべ。
一度開いたら明滅は止まる。

内容はできるだけ短くしてある。

- **「ある」と答えたカードの一番左上の数字を足していくだけです。**
- イントロで当てた数字を例に、6枚の「ある / ない」と足し算を並べて見せる
- なぜ当たるのか（1/2/4/8/16/32 は2進数。1〜60 はこの6つの足し算でただ1通りにしか表せない）
- 赤や緑の色に意味はないこと

イントロをスキップした人には、例として 37 を使う。

イントロと種明かしだけが `solve.js`（答えを出すコード）を使う。
手品の本番（`PerformanceScreen.js`）は import していない。

## 練習モード

起動画面の「練習」から。アプリが観客役をやる。通常モードの練習用。

1. 人数（1〜5人）と1枚あたりの時間（自分のペース / 5秒 / 3秒 / 2秒）を選ぶ
2. カードがめくれるたびに、全員の「ある / ない」が下に一斉に出る
3. 頭の中で人数ぶんの合計を同時に追う
4. 6枚終わったら、それぞれの数字を入力して採点

採点画面には正解とその内訳（`1 + 4 + 32`）が出るので、どこで足し間違えたか分かる。所要時間も出る。

制限時間を選ぶとタップ不要で自動的にめくれる。2秒はかなり厳しい。

### 入力

数字は1〜60なので最大2桁。**2桁入れると自動で次の人へ移る。**
7 / 8 / 9 は 70 以上になれないため、1桁でもその場で確定して次へ進む。
1〜6 は2桁目を待つので、1桁で確定したいときは「次の人」を押す。

### 記録

- **全問正解の連続回数**と、その最高記録
- **人数 × 制限時間の組み合わせごとのベストタイム**（全問正解したときだけ更新）
- 直近の履歴

自己ベストを更新すると採点画面にバッジが出る。記録は端末内にのみ保存され、
残るのは練習の成績だけ（手品の答えは何も保存しない）。練習の設定画面の「記録を消す」で消せる。

記録のキーは人数と制限時間の**言語に依存しない ID**（`3` / `pace` など）で持つ。
日本語のラベルで保存されていた古い記録は、読み込み時に ID へ移行する。

### 本番と練習の境界

練習モードは性質上、答えを計算する必要がある。そのコードは `practice.js` に閉じ込めてあり、
**`PerformanceScreen.js` からは一切 import していない**。

```
PerformanceScreen が読み込むファイル: cards.js, ui.js, ThemeContext.js, i18n.js
```

本番の画面に答えを知る手段がないことは、バンドルの依存関係で確認できる。

## 設定（配色とフォント）

起動画面の「設定」から。選ぶとその場で反映され、次回起動時も同じ設定で開く。

- **カードの配色**：ネイビー / レッド / アイボリー（`theme.js` の `PALETTES`）
- **フォント**：Avenir Next / Georgia / Academy Engraved LET（`theme.js` の `FONTS`）
- **スリープ防止**：プレイ中、画面を暗くしない（初期値オン）

スリープ防止が効くのは通常モードと練習モードの画面を開いている間だけ。設定は `prefs.js` に
保存され、`PerformanceScreen.js` / `PracticeScreen.js` が画面を開くときに読んで
`expo-keep-awake` を有効にし、画面を閉じるときに戻す。

フォント名は OS ごとに違うので、`theme.js` で `process.env.EXPO_OS` を見て出し分けている。
`Platform.select({ web: ... })` は web ビルドの変換で web キーが落ちてフォント名が消えるため使わない。

## 表示言語

端末の言語が日本語（`ja`）なら日本語、それ以外はすべて英語。切り替え UI は持たない。
文言はすべて `i18n.js` の辞書にあり、画面側は `t('key')` で引く。

判定には `expo-localization` の `getLocales()` を使う。iOS の `Intl` はアプリが対応を宣言した
言語しか返さないため、端末が日本語でも Expo Go では英語と判定されてしまう。

```js
import { t } from './i18n';

t('home.start');                 // はじめる / Start
t('intro.lead1', { max: 60 });   // 変数は {max} のように埋め込む
```

文言を足すときは `ja` と `en` の両方に同じキーを書く。
`en` に無いキーはキー文字列そのものが出るので、追加漏れは画面で分かる。

## カードの数字を変えたいとき

`cards.js` の `MAX_NUMBER` を変えるだけ。
たとえば `63` にすれば 6枚のまま 1〜63 に、`31` にして `BITS` から `32` を消せば 5枚で 1〜31 になる。
グリッドの行数（`ROWS`）も文字サイズも自動で追従する。

`COLUMNS` は1行あたりの数字の個数。少なくすると数字が大きくなる（初期値 4）。
`ACCENT_PER_CARD` は色をつける個数（初期値 7）、`ACCENT_COLORS` は赤と緑の色コード。

## 設計メモ

- 手品の本番の画面には、結果を計算する経路が**存在しない**（`solve.js` / `practice.js` を import しない）
- 進捗表示（1 / 6 など）は出さない。実物のカードに進捗表示はないため
- 画面遷移は「右から次のカードが差し込まれる」だけ。派手な演出はしない
- ステータスバーは非表示、向きは縦固定
- 端末がスリープすると手品や練習が途切れるので、通常モードと練習モードの画面では
  `expo-keep-awake` で画面を起こしたままにする（設定でオフにできる）
